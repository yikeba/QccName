Namespace 解决什么问题What Namespace solves

传统账户 = 平台数据库里的一行记录。账户能不能用、会不会被盗、被盗后能不能找回，全部取决于平台。Namespace 把这一行记录搬到用户手里。A traditional account is a row in a platform's database. Whether it works, whether it gets stolen, whether you can get it back — all of that is up to the platform. Namespace moves that row into the user's hands.

① 去中心化账户：归属权在用户① Decentralized accounts: users own them

名字由用户私钥签名注册，链上质押背书，规则写在链上协议里。平台不能封号、改号、没收名字；节点也伪造不了。同一个 alice.qcc 可以登录任何接入的应用，不必在每个平台各开一个账户。A name is registered with the user's own signature, backed by an on-chain pledge, under rules anchored on-chain. No platform can ban, rename or confiscate it, and no node can forge it. The same alice.qcc signs in to every integrated app — no account per platform.

② 从根上去掉平台侧的盗号路径② Removes the platform-side theft paths

没有密码，就没有撞库和弱口令；没有账户数据库，就没有拖库泄露；没有"客服找回"和短信验证码，就没有社工和 SIM 换卡。登录是抗量子签名 + 多节点独立核对，任何人都能复核证据。剩下的风险只在用户自己的签名私钥上，第 ③④ 点专门处理它。No password means no credential stuffing or weak passwords; no account database means nothing to breach; no "support recovery" or SMS codes means no social engineering or SIM swaps. Sign-in is a post-quantum signature checked independently by several nodes, and anyone can re-check the evidence. The remaining risk sits in the user's own signing key — which ③ and ④ address.

③ 被盗也能立即止损：撤销质押③ Stop the damage instantly: revoke the pledge

名字的有效性每次核验都实时查链。签名私钥一旦泄露，在资产钱包撤销授权质押，名字立刻变成 REVOKED，所有接入的应用在下一次核验时一起拒绝它，不需要联系任何平台。名字随后被回收并进入冷却期，期间谁都不能注册。Every verification re-checks the pledge on-chain. If a signing key leaks, revoke the pledge from the asset wallet: the name turns REVOKED at once and every integrated app rejects it on its next check — no platform to call. The name is then reclaimed and enters a cooldown during which nobody can register it.

④ 双钱包分离：服务器间也能安全鉴权④ Two-wallet model: safe server-to-server auth

资产钱包离线保管、只负责质押与撤销；签名钱包是 0 资产地址，放在 App 或服务器里日常签名。服务器用自己的名字（如 api.osn）和签名钱包互相鉴权：密钥放在服务器上，泄露了也动不了资产，撤销质押就能吊销这台服务器的身份。The asset wallet stays offline and only pledges or revokes; the signing wallet holds zero assets and signs day-to-day inside an app or a server. Servers authenticate each other by their own names (e.g. api.osn) and signing wallets: a key on a server, if leaked, cannot move funds, and revoking the pledge retires that server's identity.

从经济模型上让盗号无利可图Making account theft unprofitable by design

盗号是生意：成本低、规模大、能变现，才有人做。Namespace 同时打掉这三点。Account theft is a business: it pays when it is cheap, scalable and easy to cash out. Namespace removes all three.

批量 → 逐个Bulk → one by one

平台被拖库一次就是几百万个账户，攻击成本摊到每个账户几乎为零。这里没有中心数据库，攻击者只能一台设备一台设备地攻破，成本随账户数线性增长。One platform breach yields millions of accounts at near-zero cost each. With no central database, an attacker must compromise devices one at a time — cost grows linearly with every account.

盗了也难变现Hard to cash out

签名钱包是 0 资产地址，拿到私钥也转不走一分钱；质押锁在资产钱包名下，只有资产钱包能撤销。名字绑定地址，没有"过户"操作，无法转卖。The signing wallet holds zero assets, so its key moves no funds; the pledge stays under the asset wallet, which alone can revoke it. A name is bound to its address with no transfer operation, so it cannot be resold.

可用窗口极短A tiny window

用户发现异常，撤销一笔质押，名字在全网立即失效，不用排队等客服。盗来的身份能用的时间以分钟计，期望收益随之趋近于零。Once the user notices, one revoke invalidates the name network-wide — no support queue. A stolen identity is usable for minutes, so its expected value approaches zero.

反过来，造假号也有真实成本：每个名字都要锁定 ≥1 QCC 的质押，批量注册僵尸号、囤名的成本随数量线性上升。高价值的定向攻击仍然可能发生，但大规模、低成本的盗号产业在这里没有土壤。Conversely, fake accounts cost real money: every name locks ≥1 QCC, so bot farms and name hoarding scale linearly in cost. Targeted attacks on high-value identities remain possible, but cheap, mass-scale account theft has nothing to grow on.

诚实的边界：Namespace 去掉的是平台侧的盗号路径。用户设备被入侵、或在钓鱼页面上签了名，签名私钥仍可能被利用 —— 所以有第 ③④ 点：私钥只放在 0 资产的签名钱包里，并且可以一键吊销。助记词与资产钱包请离线保管。Honest boundary: Namespace removes the platform-side theft paths. If a user's device is compromised or they sign on a phishing page, the signing key can still be abused — which is why ③ and ④ exist: the key lives only in a zero-balance signing wallet and can be revoked in one step. Keep the mnemonic and asset wallet offline.

对应用运营方的好处What apps gain

接入 QCC-Auth，应用不再需要自己维护一套账户系统 —— 账户、凭证、找回、吊销都由用户和链来承担。With QCC-Auth an app no longer runs its own account system — accounts, credentials, recovery and revocation are carried by the user and the chain.

省掉短信验证码No SMS verification

注册、登录、找回都不用发短信：没有按条计费，没有国际短信的高价，也没有"短信轰炸 / 刷量"欺诈带来的账单。No SMS for sign-up, sign-in or recovery: no per-message fees, no international SMS rates, and no bills from SMS-pumping fraud.

不存密码，不存手机号No passwords, no phone numbers

数据库里只有名字和公开地址，没有可泄露的密码哈希和个人信息，个人数据合规的负担和泄露事故的责任都大幅下降。The database holds only names and public addresses — no password hashes or personal data to leak — cutting data-protection burden and breach liability.

天然防机器人、防薅羊毛Built-in anti-bot, anti-abuse

每个名字背后锁着链上质押，应用还能设自己的门槛（如质押 ≥ 10 QCC 才能领补贴）。批量注册小号的成本随数量线性上升。Every name has an on-chain pledge behind it, and apps can set their own bar (e.g. ≥ 10 QCC to claim a promotion). Farming accounts costs more with every account.

一个名字，所有应用One name, every app

用户不必在每个应用重新注册，接入即可登录，转化率更高。也不依赖 Apple / Google 账号登录，不受平台政策、封号和地区限制影响。Users sign in without signing up again, which lifts conversion — and without depending on Apple or Google sign-in, platform policies, bans or regional limits.

身份与收款合一Identity and payments in one

登录用的名字同时就是收款地址：转账给 chen.qcc，不用再绑定银行卡或另记一串地址。The name you sign in with is also where you get paid: send to chen.qcc, no card binding, no extra address to copy.

不可抵赖、可审计Non-repudiable, auditable

每次登录和授权都是用户的抗量子签名，事后可以向任何第三方证明"是本人操作"，适合金融、企业、政务场景的审计要求。Every sign-in and approval is the user's post-quantum signature, provable to any third party afterwards — fit for audit needs in finance, enterprise and government.

不用做"找回账户"No account recovery desk

没有忘记密码，没有客服核实身份。用户丢了签名钱包，用资产钱包撤销质押、换新钱包重新授权即可，应用侧零工作量。No forgotten passwords, no identity checks by support. If a user loses the signing wallet, they revoke from the asset wallet and authorize a new one — zero work on the app side.

长期安全：抗量子Long-term safety: post-quantum

签名采用 ML-DSA-87（NIST 标准最高等级），现在接入，不必等量子计算机出现后再迁移整套账户体系。Signatures use ML-DSA-87 (the highest NIST level). Integrate once — no need to migrate the whole account system when quantum computers arrive.

在传统互联网，.com、.cn 由机构分配、按年续费，随时可能被收回。在 QCC 上，tag 是链上资产：谁发起交易，就归谁。On the traditional internet, .com and .cn are allocated by institutions, renewed yearly and can be taken back. On QCC a tag is an on-chain asset: whoever sends the transaction owns it.

永久归属，不用续费Owned for good, no renewals

注册成功后，tag 永久归属交易发起方。没有年费、没有到期、没有人能收回 —— 所有权就写在链上，任何人可查。Once registered, the tag belongs to the sender permanently. No annual fee, no expiry, nobody to take it back — ownership is on-chain for anyone to check.

不只是域名后缀，也可以是一段故事Not just a suffix — it can be a story

开源行业示范：一个 tag，一套账户体系An open industry template: one tag, one account system

Namespace 是开源的参考实现。任何行业都可以 fork 一份，换成自己的 tag 和资产，几乎不用改代码，就得到一套属于自己生态的去中心化账户体系。Namespace is an open-source reference implementation. Any industry can fork it, swap in its own tag and asset with almost no code changes, and get a decentralized account system for its own ecosystem.

行业自己定规则Each industry sets its rules

准入门槛、等级写在自己的链上协议里，管理名由发布者的 Reserved 决定。需要实名的金融场景，可以在 fork 里加上 KYC；社交、内容、游戏可以完全匿名。Entry bar and tiers live in its own on-chain protocol; management names come from the publisher's Reserved. Finance can add KYC in its fork; social, content and games can stay fully pseudonymous.

账户归用户，服务归应用Users own accounts, apps own service

应用可以对某个账户停止服务，但名字仍属于用户，在其他应用照常可用。应用管得了自己的服务，管不了用户的身份。An app can stop serving an account, but the name stays the user's and keeps working elsewhere. Apps control their service, not the user's identity.

资产就是会员体系The asset is the membership

质押多少就是什么等级，链上可查、不能伪造。不用单独开发会员、积分、等级系统。How much you pledge is your tier — verifiable on-chain, impossible to fake. No separate membership, points or tier system to build.

Reserved：企业级 namespace 的管理边界Reserved: the management boundary of an enterprise namespace

公开的 namespace 人人可注册、先到先得，协议里不内置任何保留名。企业需要 admin、support、audit 这样的内部管理名，而且要能随时换人 —— 这些名字写死在协议里，换一次人就要发一版新协议。Reserved 把管理名从协议里拿出来：由协议发布者单独签名上链，名字对应的地址随时可以更新。A public namespace is open to everyone, first come first served, with no reserved names built into the protocol. An enterprise needs internal management names such as admin, support and audit, and must be able to reassign them at any time — hard-coding them into the protocol would mean a new protocol for every staff change. Reserved takes management names out of the protocol: the protocol publisher signs and anchors them separately, and the address behind each name can be updated at any time.

只有发布者能发Only the publisher

谁发布了 qcc-name 协议，谁就是 Reserved 的发布者：节点取回协议所在交易，交易的 from 就是唯一能发 Reserved 的地址。不新增任何信任根。Whoever published the qcc-name protocol publishes Reserved: nodes fetch the protocol transaction, and its from is the only address allowed to publish Reserved. No new root of trust.

历史全部保留Full history kept

每一版都是完整的表，seq 逐版加 1，prevTx 指向上一版的交易，按区块高度生效。任何时刻谁是 admin，都能在链上查到、可以审计。Every version is a complete table; seq increases by one, prevTx points to the previous transaction, and the block height decides when it takes effect. Who was admin at any moment is on-chain and auditable.

全网同时切换The whole network switches together

主节点向多个 QCC 链节点取回交易并一致确认后，写入一条 reserve 日志；其他节点从日志同步。所有节点在同一个点切换，不受各自读链快慢影响。The primary fetches the transaction from several QCC chain nodes, confirms they agree, and writes one reserve entry to the log; other nodes sync it. Every node switches at the same point, regardless of when it reads the chain.

技术特性Technical features

抗量子地址很长，没人记得住，也很容易抄错。传统用户名又掌握在平台手里。Namespace 让名字归用户自己所有：规则写在链上，结果人人可验。Post-quantum addresses are long, impossible to remember and easy to mistype. Traditional usernames belong to platforms. Namespace makes names belong to their users: the rules live on-chain and the results are verifiable by anyone.

抗量子签名Post-quantum signatures

注册、删除都由用户的 ML-DSA-87 私钥签名，与 QCC 链使用同一套密码学。Every register / unregister is signed with the user's ML-DSA-87 key — the same cryptography as the QCC chain.

结果可验证（L1）Verifiable results (L1)

查询结果附带用户原始签名与签名原文。客户端自己验签，不需要信任任何节点。Lookups return the user's original signature and signed string. Clients verify it themselves — no node needs to be trusted.

质押防抢注Pledge-backed, anti-squatting

注册前必须先做授权质押（≥1 QCC）。撤销质押，名字随之失效并回收，批量囤名有真实成本。An authorized pledge (≥1 QCC) is required. Revoke it and the name lapses and is reclaimed — hoarding names has a real cost.

协议上链Protocol on-chain

全部规则（格式、形近字、冷却期、Reserved 的发布规则）写在引导协议里，以 hash 锚定在 QCC 链上，节点按 hash 加载。All rules (format, confusables, cooldown, how Reserved is published) live in a bootstrap protocol anchored on QCC by hash; nodes load it by hash.

P2P 多节点P2P multi-node

节点 P2P 组网，主节点故障时自动选举接班；IPv6 冗余节点做数据备份；节点间通讯 AES-256-GCM 加密。Nodes form a P2P cluster with automatic failover; IPv6 backup nodes keep redundant copies; inter-node traffic is AES-256-GCM encrypted.

开源 · 零依赖Open source · zero deps

节点用纯 Java 编写（JDK 自带 HTTP / AES / ML-DSA），单个 jar 即可运行，256MB 的 VPS 也能部署。Pure Java (JDK HTTP / AES / ML-DSA), a single jar, deployable on a 256 MB VPS.

去中心化如何实现How decentralization works

节点只负责排序和执行规则，不掌握任何人的名字。名字属于持有私钥的人，资格来自链上质押，规则来自链上协议。Nodes only order operations and apply rules — they own no one's name. A name belongs to whoever holds the key; eligibility comes from the on-chain pledge; rules come from the on-chain protocol.

01 · CHAIN链上授权质押On-chain pledge资产钱包把 ≥1 QCC 授权质押给签名钱包，tag = qccio，交易 hash 即凭证。Asset wallet pledges ≥1 QCC to a signing wallet under tag qccio; the tx hash is the credential.
02 · SIGN用户签名User signs签名钱包对 QNS1|register|…|credentialHash 做 ML-DSA-87 签名。The signing wallet signs QNS1|register|…|credentialHash with ML-DSA-87.
03 · NODE节点按协议执行Nodes apply rules验签 → 查链上质押 → 按协议顺序检查 → 写入帧日志，复制到过半核心节点。Verify signature → check pledge on-chain → run checks in protocol order → append to the frame log, replicated to a majority.
04 · VERIFY任何人核验Anyone verifiesverify 返回签名原文与签名，再到链上确认质押仍然有效。撤销后立即显示 REVOKED。verify returns the signed string and signature, and re-checks the pledge on-chain. A revoked pledge shows REVOKED immediately.

两个钱包，职责分离Two wallets, separated duties

资产钱包持有 QCC、发起质押，只有它能撤销。签名钱包是 0 资产地址，只用于签名和持有名字。签名钱包的私钥放在应用里，即使泄露也动不了资产；在资产钱包撤销质押，名字随即失效。The asset wallet holds QCC, makes the pledge, and is the only one who can revoke it. The signing wallet is a zero-balance address used only to sign and hold the name. Its key can live in your app: a leak cannot move funds, and revoking from the asset wallet kills the name.

节点作恶怎么办What if a node misbehaves

节点无法伪造用户签名，所以没法凭空造出一个名字。每一帧都进入 execHash 链，各节点的 execHash 必须一致，分叉立即暴露。协议 hash 锚定在链上，节点改不了规则。A node cannot forge user signatures, so it cannot invent a name. Every frame enters the execHash chain; all nodes must agree on it, so forks are exposed immediately. The protocol hash is anchored on-chain, so nodes cannot change the rules.

授权质押（tag 质押）Authorized pledge (tag pledge)

资产钱包发起一笔质押规则交易：把 ≥1 QCC 授权质押给签名钱包，绑定 tag qccio。交易上链后，交易 hash 就是之后注册用的 credentialHash。The asset wallet submits a pledge rule transaction: authorize ≥1 QCC to the signing wallet under tag qccio. Once on-chain, the tx hash becomes the credentialHash used for registration.

// 规则交易要素（提交到 QCC 节点 /v1/rule，由资产钱包签名）
type      = AuthorizedPledge · lock
from      = QAssetWallet…                         // 质押方：唯一可撤销者
to        = QWasmDyBQzCTdUhj6NLyfAzU6z5sTSdhM1   // 被授权的签名钱包
tag       = "qccio"
amount    = 1000000000                            // 1 QCC（NanoQCC）

# 确认上链，拿到 credentialHash
GET /v1/hash/{txHash}                     → status = SUCCESS
# 确认授权质押已生效
GET /v1/pledge/{to}?tag=qccio&hash={txHash}&minAmount=0
完整的 Java 质押、撤销示例见开源仓库中的 qcctest（QccNameTestKit.pledge() / revoke()）。质押可以随时撤销：资金回到资产钱包，名字随之失效。Full Java pledge / revoke examples are in qcctest in the open-source repo (QccNameTestKit.pledge() / revoke()). A pledge can be revoked anytime: funds return to the asset wallet and the name lapses.
